Купец Афанасий каждый вечер записывает в приходно-расходную книгу итог дня в копейках: прибыль — с плюсом, убыток —
с минусом. К ярмарке он хочет похвастаться самой удачной полосой: несколькими днями подряд, которые в сумме принесли
больше всего. Пустой полоса быть не может: если убыточны все дни, хвастаться придётся наименее убыточным из них.

Дан массив `A` из `N` целых чисел: `A[i]` — итог дня `i`. Найдите наибольшую сумму подряд идущих дней:

```
R[0] = max(A[l] + A[l+1] + ... + A[r]) по всем 0 ≤ l ≤ r < N
```

Сумма может не поместиться в 32 бита, поэтому ответ 64-битный.

Задачу можно сдать на видеокарте (`gpu-cuda`), на её симуляторе (`cuda-sim`), как схему (`rtl`), на векторном
процессоре RISC-V (`riscv-rvv`) и на ядре Coral NPU (`coral-npu`).

Реализуйте функцию

```cpp
void solve(const int* A, int64_t* R, int N);
```

`A` и `R` лежат в памяти GPU; в `R` один 64-битный элемент. `solve` выполняется на CPU: она запускает ядра
и возвращается, проверяющая система сама дожидается их завершения. Привычный цикл по дням последователен: каждый шаг
ждёт предыдущего. Но куски книги можно обработать независимо, если про каждый запомнить чуть больше, чем его лучшую
полосу: тогда итоги двух соседних кусков склеиваются в итог их объединения.

## На симуляторе GPU (`cuda-sim`)

Та же `solve` на CUDA исполняется в GPGPU-Sim на модели NVIDIA Tesla V100 (QV100). Score — число тактов
симулируемой видеокарты: чем меньше, тем лучше. `cudaMemcpy*` и обмен между потоками варпа (`__shfl_*_sync`)
в решении запрещены.

## Как схема (`rtl`)

Решение — модуль `solve` на SystemVerilog со входом `N`, входным потоком и выходом из одного элемента. Проверяющая
система поднимает `start` на первый такт и со следующего такта подаёт по одному элементу за такт: пока поднят
`A_valid`, на `A_data` лежит `A[i]`. Отдайте ответ: поднимите `R_valid` на один такт и выставьте сумму на 64 битах
`R_data`, затем поднимите `done`. Поток нельзя ни приостановить, ни перемотать. До `start` все регистры равны нулю.
Score — число тактов до `done`, умноженное на глубину логики (наибольшее число вентилей на пути между регистрами)
и на число транзисторов синтезированной схемы: чем меньше, тем лучше. Схема должна быть синхронной: без защёлок
и асинхронных сбросов. Какой ширины нужны сумматоры, говорят ограничения ниже.

## На RISC-V (`riscv-rvv`)

Та же `solve` на C, C++ или ассемблере RISC-V для RV64GCV с векторами по 256 бит; массивы лежат в обычной памяти.
Score — число выполненных инструкций плюс 10 за каждый промах кэша L1 и 100 за каждый промах L2: чем меньше,
тем лучше.

## На Coral NPU (`coral-npu`)

Та же `solve` на C или C++ для ядра Coral NPU без операционной системы: RV32IMF с Zbb и векторами по 128 бит
(Zve32x, Zve32f), стандартной библиотеки C++ нет. У ядра 8 КБ памяти под код и 32 КБ под данные; массивы лежат
в этой памяти данных. Score — число инструкций, выполненных ядром: чем меньше, тем лучше. В C++ объявляйте `N`
как `int32_t`, как в шаблоне решения: на этой платформе `int32_t` — это `long`, и `solve` с параметром `int` будет
другой функцией. Ядро 32-битное: 64-битное число занимает в нём два регистра, и каждое сложение и сравнение с таким
числом стоит нескольких инструкций.

## Пример

| A | R |
| --- | --- |
| -200 400 -100 250 -700 300 150 -50 | 550 |

Лучшая полоса — дни с 1 по 3: 400 − 100 + 250 = 550 копеек. Убыточный день внутри неё выгоднее пережить, чем
обрывать на нём полосу. А вот убыток в 700 копеек уже не окупается: продолжать полосу через него незачем, а дни 5 и 6
сами по себе дают только 450.

## Ограничения

- 1 ≤ N ≤ 10 000 000 на видеокарте, 1 ≤ N ≤ 4096 на `rtl`, 1 ≤ N ≤ 100 000 на `riscv-rvv` и `cuda-sim`,
  1 ≤ N ≤ 6000 на `coral-npu`;
- −1 000 000 ≤ A[i] ≤ 1 000 000;
- ответ сравнивается точно.
