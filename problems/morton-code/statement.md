Картографический сервис режет карту мира на плитки: 65 536 столбцов и 65 536 строк. Все плитки лежат в одном файле
в порядке Z-кривой: номер плитки в файле получается, если перемешать биты номера столбца и номера строки, как две
половины колоды — через один. Плитки, соседние на карте, при таком порядке обычно оказываются рядом и в файле,
и экран карты читается с диска почти одним куском.

Даны массивы `X` и `Y` из `N` целых чисел: `X[i]` — столбец плитки, `Y[i]` — её строка. Для каждой плитки найдите
номер в файле `C[i]`. Биты нумеруются с нуля, начиная с младшего:

```
бит 2k числа C[i]     = бит k числа X[i]
бит 2k + 1 числа C[i] = бит k числа Y[i]        (k = 0, 1, ..., 15)
```

Задачу можно сдать на видеокарте (`gpu-cuda`), на её симуляторе (`cuda-sim`), как схему (`rtl`), на векторном
процессоре RISC-V (`riscv-rvv`) и на ядре Coral NPU (`coral-npu`).

Реализуйте функцию

```cpp
void solve(const uint32_t* X, const uint32_t* Y, uint32_t* C, int N);
```

`X`, `Y` и `C` лежат в памяти GPU. `solve` выполняется на CPU: она запускает ядра и возвращается, проверяющая система
сама дожидается их завершения. Переставлять биты по одному — это 32 шага на плитку; раздвигать их можно и целыми
группами. А в схеме перестановка битов не стоит вообще ничего.

## На симуляторе GPU (`cuda-sim`)

Та же `solve` на CUDA исполняется в GPGPU-Sim на модели NVIDIA Tesla V100 (QV100). Score — число тактов
симулируемой видеокарты: чем меньше, тем лучше. `cudaMemcpy*` и обмен между потоками варпа (`__shfl_*_sync`)
в решении запрещены.

## Как схема (`rtl`)

Решение — модуль `solve` на SystemVerilog. `X`, `Y` и `C` — память проверяющей системы: выставьте индекс на `X_addr`,
и на следующем такте элемент придёт на `X_data` (так же устроены `Y_addr` и `Y_data`); запись `C[C_addr] = C_data`
происходит на такте, где поднят `C_write`. Проверяющая система поднимает `start` на первый такт; поднимите `done`,
когда записаны все элементы `C`. До `start` все регистры равны нулю. Score — число тактов до `done`, умноженное
на глубину логики (наибольшее число вентилей на пути между регистрами) и на число транзисторов синтезированной схемы:
чем меньше, тем лучше. Схема должна быть синхронной: без защёлок и асинхронных сбросов. Перемешать биты — значит
соединить провода, так что вся логика схемы уходит на обход массива: считать score будут по ней.

## На RISC-V (`riscv-rvv`)

Та же `solve` на C, C++ или ассемблере RISC-V для RV64GCV с векторами по 256 бит; массивы лежат в обычной памяти.
Score — число выполненных инструкций плюс 10 за каждый промах кэша L1 и 100 за каждый промах L2: чем меньше,
тем лучше.

## На Coral NPU (`coral-npu`)

Та же `solve` на C или C++ для ядра Coral NPU без операционной системы: RV32IMF с Zbb и векторами по 128 бит
(Zve32x, Zve32f), стандартной библиотеки C++ нет. У ядра 8 КБ памяти под код и 32 КБ под данные; массивы лежат
в этой памяти данных. Score — число инструкций, выполненных ядром: чем меньше, тем лучше. В C++ объявляйте `N`
как `int32_t`, как в шаблоне решения: на этой платформе `int32_t` — это `long`, и `solve` с параметром `int` будет
другой функцией.

## Пример

| X | Y | C |
| --- | --- | --- |
| 0 1 0 3 65535 65535 | 0 0 1 5 0 65535 | 0 1 2 39 1431655765 4294967295 |

У плитки в столбце 3 = `011₂` и строке 5 = `101₂` биты строки `1 0 1` встают на нечётные места, а биты столбца
`0 1 1` — на чётные: получается `100111₂` = 39. У плитки в столбце 65 535 и строке 0 заняты все чётные биты номера,
это 1 431 655 765, а у последней плитки карты — все 32.

## Ограничения

- 1 ≤ N ≤ 10 000 000 на видеокарте, 1 ≤ N ≤ 4096 на `rtl`, 1 ≤ N ≤ 100 000 на `riscv-rvv` и `cuda-sim`,
  1 ≤ N ≤ 2000 на `coral-npu`;
- 0 ≤ X[i], Y[i] ≤ 65 535;
- ответ сравнивается точно.
