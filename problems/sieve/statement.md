В шифровальном бюро ключи собирают из простых чисел, и перед каждой сменой на стену вешают свежую таблицу: напротив
каждого числа от 0 до N − 1 стоит единица, если оно простое, и ноль, если нет. Стажёр Петя составлял такую таблицу,
честно пробуя для каждого числа все делители подряд, — и к началу смены не успел. Завтра таблицу поручили вам.

Дано число `N`. Заполните массив `C` из `N` байтов:

```
C[i] = 1, если i простое, и 0 иначе
```

Простое число — это целое число больше 1, которое делится только на 1 и на само себя; 0 и 1 простыми не считаются.
Входных массивов в задаче нет.

Задачу можно сдать на видеокарте (`gpu-cuda`), на её симуляторе (`cuda-sim`), на векторном процессоре RISC-V
(`riscv-rvv`) и на ядре Coral NPU (`coral-npu`).

Реализуйте функцию

```cpp
void solve(uint8_t* C, int N);
```

`C` лежит в памяти GPU. `solve` выполняется на CPU: она запускает ядра и возвращается, проверяющая система сама
дожидается их завершения. Пробовать все делители каждого числа слишком долго: лимиты рассчитаны на решето Эратосфена.
Но решето идёт по простым числам по очереди и каждый раз проходит всю таблицу: как раздать такую работу потокам,
векторам и кэшу, на каждом процессоре приходится решать заново.

## На симуляторе GPU (`cuda-sim`)

Та же `solve` на CUDA исполняется в GPGPU-Sim на модели NVIDIA Tesla V100 (QV100). Score — число тактов
симулируемой видеокарты: чем меньше, тем лучше. `cudaMemcpy*` и обмен между потоками варпа (`__shfl_*_sync`)
в решении запрещены. Такты симулятора — это время, а не объём работы: потоки считают одновременно, зато длинная
цепочка делений или обращений к памяти в одном потоке стоит дорого. Самое дешёвое решение здесь может быть устроено
иначе, чем на настоящей видеокарте.

## На RISC-V (`riscv-rvv`)

Та же `solve` на C, C++ или ассемблере RISC-V для RV64GCV с векторами по 256 бит; массивы лежат в обычной памяти.
Score — число выполненных инструкций плюс 10 за каждый промах кэша L1 и 100 за каждый промах L2: чем меньше,
тем лучше. Таблица из 100 000 байтов больше кэша L1 (32 КиБ): решето, которое для каждого простого числа проходит её
целиком, платит промахами.

## На Coral NPU (`coral-npu`)

Та же `solve` на C или C++ для ядра Coral NPU без операционной системы: RV32IMF с Zbb и векторами по 128 бит
(Zve32x, Zve32f), стандартной библиотеки C++ нет. У ядра 8 КБ памяти под код и 32 КБ под данные; массивы лежат
в этой памяти данных. Score — число инструкций, выполненных ядром: чем меньше, тем лучше. В C++ объявляйте `N`
как `int32_t`, как в шаблоне решения: на этой платформе `int32_t` — это `long`, и `solve` с параметром `int` будет
другой функцией. Таблица занимает большую часть памяти данных: на вторую такую же места нет.

## Пример

| N | C |
| --- | --- |
| 20 | 0 0 1 1 0 1 0 1 0 0 0 1 0 1 0 0 0 1 0 1 |

Простые числа меньше 20 — это 2, 3, 5, 7, 11, 13, 17 и 19: на этих местах в таблице стоят единицы.

## Ограничения

- 3 ≤ N ≤ 10 000 000 на видеокарте, 3 ≤ N ≤ 100 000 на `riscv-rvv` и `cuda-sim`, 3 ≤ N ≤ 24 000 на `coral-npu`;
- ответ сравнивается точно.
